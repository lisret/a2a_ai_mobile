# NoNo VLM 一键启动与动态输入帧数设计

## 目标

为本地实时摄像头 VLM 工具提供一个一键启动入口，并允许在网页调试台中动态调整变化场景每秒提交给 VLM 的图片数量。

成功标准：

- 在 `tools/realtime_camera` 中执行一个脚本即可启动摄像头、快速分析、VLM sidecar 和网页调试台。
- 脚本默认自动打开 `http://127.0.0.1:8765/`。
- 默认仍为每秒一张图片，保持当前低延迟路径。
- 调试台可将变化场景输入帧数热调整为 1～4 张，无需重启摄像头或 VLM。
- 静止/变化判断沿用现有快速分析结果；静止场景始终只提交最新一张。
- VLM 忙时继续遵守 latest-only 背压，不积压历史窗口。
- `Ctrl-C` 能关闭完整流程并释放摄像头和 sidecar。

## 用户入口

新增可执行脚本：

```text
tools/realtime_camera/run_vlm_camera.sh
```

在仓库任意工作目录中可直接执行该脚本。脚本先解析自身所在目录，再从工具目录运行，因此不依赖调用者当前目录。

脚本负责：

1. 检查 `uv` 是否可用；缺失时给出明确安装提示并退出。
2. 如果 `.venv` 或已锁定依赖尚未准备好，执行 `uv sync --extra vlm`。
3. 检查 EfficientDet-Lite0 模型；缺失时下载到 Git 忽略的 `.runtime/models/`，并校验既有 SHA256。
4. 创建 Matplotlib 与 Hugging Face 运行时目录。
5. 启动 `nono-camera dashboard --vlm --open`，使用当前小模型和低延迟参数。
6. 将终止信号交给前台 Python 进程，使现有资源清理逻辑负责释放摄像头和 sidecar。

默认参数允许通过环境变量覆盖摄像头编号、dashboard/VLM 端口和是否自动打开浏览器，但不在脚本中复制 Python 侧所有可热调参数。

## 动态输入帧数

### 配置合同

在 `DashboardConfigV1` 增加 `semantic_dynamic_frame_count`：

- 默认值：`1`
- 合法范围：`1～4`
- API 字段：`semanticDynamicFrameCount`
- 调试台控件：范围滑块或等价的整数控件

该字段表示“检测到变化时，本秒窗口最多提交多少张图片”，而不是 VLM 调用频率。VLM 冷却时间仍独立控制多久触发一次语义任务。

### 选帧规则

沿用现有 `latest` 与 `adaptive` 的用户语义，但将其统一到热配置：

- `semantic_dynamic_frame_count = 1`：无论静止或变化，只选择最后一帧，等价于当前默认 `latest` 快速路径。
- `semantic_dynamic_frame_count > 1` 且场景静止：只选择最后一帧。
- `semantic_dynamic_frame_count > 1` 且存在运动、场景变化或摘要变化：从一秒窗口内按时间均匀选择最多 N 帧，并保证包含窗口首帧和末帧。
- 如果窗口实际帧数少于 N，去重后只返回现有帧。

调试台修改后，配置 revision 递增；下一次形成语义任务时读取最新值。已经提交的任务不修改，也不取消。

命令行现有 `--vlm-input-mode` 保留兼容：

- `latest` 初始化动态帧数为 1。
- `adaptive` 初始化动态帧数为 3。
- 页面修改后以热配置值为准。

## 数据流与性能边界

```text
摄像头窗口
  -> 快速分析判断静止/变化
  -> 读取 semanticDynamicFrameCount
  -> 静止选 1 帧 / 变化均匀选 1～4 帧
  -> latest-only SemanticWorker
  -> MLX-VLM sidecar
  -> 页面显示完整结果与本次实际输入帧数
```

增加图片可能提高动作和变化理解，但视觉编码耗时会随输入帧数增加。该功能不承诺 2～4 帧仍低于 1 秒；调试台已有处理耗时、P50/P95、pending、drop 和 stale 指标，供用户现场选择质量与速度的平衡点。

快速通道、MJPEG 预览和摄像头采集不等待 VLM。若多帧推理超过一秒，worker 仍只保留最新待处理任务。

## 错误处理

- `uv` 缺失：脚本输出可执行的安装提示并以非零状态退出。
- 依赖同步或模型下载失败：保留已下载缓存，输出失败阶段，不启动半配置的服务。
- 模型 SHA256 不匹配：拒绝启动对象检测，提示删除损坏文件后重试。
- 端口占用、摄像头占用或 VLM 启动失败：沿用 CLI/dashboard 的现有错误和 degraded 状态。
- 脚本收到 `INT` 或 `TERM`：转发给前台 dashboard，等待其完成资源清理。

## 验证

自动化测试覆盖：

- 脚本可执行、使用脚本自身目录、包含依赖与模型检查，并传入默认 VLM 参数。
- 默认动态帧数为 1，非法的 0 和 5 被拒绝。
- 静止窗口在任意配置下只返回一帧。
- 变化窗口分别选择 1、2、3、4 帧，并保持时间顺序、包含首尾和无重复。
- API 热更新后下一语义任务使用新帧数。
- 页面控件显示服务端值、提交更新，并避免轮询覆盖正在编辑的值。
- 本次实际输入帧数来自最新语义结果，而不是累计指标。

人工验证覆盖：

- 执行脚本后浏览器打开、摄像头画面可见、快速结果持续输出、VLM ready。
- 默认结果显示输入 1 帧。
- 将变化帧数改为 2～4，制造真实运动后确认本次输入帧数和处理耗时发生对应变化。
- 恢复为 1 后无需重启即可回到单帧路径。
- `Ctrl-C` 后确认摄像头释放，8765 和 8766 不再监听。

## 不在本次范围

- 不改变现有小 VLM 默认模型、448px 输入和 16-token 输出上限。
- 不增加帧级 VLM 连续推理。
- 不根据延迟自动回退帧数。
- 不实现变化区域 ROI、首 token 流式输出或模型 A/B 自动切换。
